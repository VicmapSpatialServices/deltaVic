VLRS client

Install and first run

The VLRS client keeps a copy of Vicmap in a PostgreSQL database on your own computer or server. This page takes you from nothing installed to your first layers loaded and kept up to date, one step at a time. Pick your system below and the instructions change to suit it.

1. PostgreSQL 2. PostGIS 3. Database 4. Spatial 5. The client 6. Register 7. Layers 8. Sync 9. Check 10. Schedule

Before you start

  1. Administrator rights on the computer, to install PostgreSQL and Python.
  2. An SSD with room for the data: about 150 GB for every layer including the history archives, under 50 GB without them, and far less for a few layers. Leave headroom on top.
  3. An email address you can open, to validate your registration.
  4. About an hour for the setup, plus several hours for a first full download of everything.

Only browsing the catalogue? Skip to step 5. PostgreSQL is only needed to download data.

1

Install PostgreSQL 18

PostgreSQL is the database the layers are copied into. Version 18 or later is required, because the data is packaged with 18.

  1. Download the installer for PostgreSQL 18 for Windows x86-64 from postgresql.org. It sends you to the EDB download page.
  2. Run it and accept the default folders.
  3. On Select Components leave all four ticked: the server, pgAdmin 4, Stack Builder and the command line tools. The client needs the command line tools.
  4. Choose a password for the postgres superuser and write it down. You need it in step 3.
  5. Keep the port at 5432 and the default locale.
  6. At the end, leave Launch Stack Builder ticked and press Finish. Stack Builder is step 2.

Use an SSDKeep the default data folder unless it is on a spinning disk. On a hard disk a sync is many times slower.

The simplest route on a Mac is Postgres.app, which comes with PostGIS built in.

  1. Download Postgres.app with PostgreSQL 18 from postgresapp.com.
  2. Drag it into Applications and open it.
  3. Press Initialize to create a server. It starts on port 5432.

The EDB installer from postgresql.org also works. If you use it, follow the Windows steps, which are the same on a Mac.

Most distributions ship an older PostgreSQL, so add the PostgreSQL project's own repository first. These commands are for Debian and Ubuntu.

The first five lines add the repository and its signing key. The last two install PostgreSQL 18 with PostGIS.

Terminal
sudo apt install -y curl ca-certificates
sudo install -d /usr/share/postgresql-common/pgdg
sudo curl -o /usr/share/postgresql-common/pgdg/apt.postgresql.org.asc --fail https://www.postgresql.org/media/keys/ACCC4CF8.asc
. /etc/os-release
echo "deb [signed-by=/usr/share/postgresql-common/pgdg/apt.postgresql.org.asc] https://apt.postgresql.org/pub/repos/apt $VERSION_CODENAME-pgdg main" | sudo tee /etc/apt/sources.list.d/pgdg.list
sudo apt update
sudo apt install -y postgresql-18 postgresql-18-postgis-3

That installs PostGIS too, so skip step 2. If the machine already runs an older PostgreSQL, version 18 takes the next free port, usually 5433. pg_lsclusters shows which, and that is the port to use in step 6.

2

Add PostGIS

PostGIS lets PostgreSQL store maps: points, lines and areas. Vicmap needs it.

  1. Stack Builder opens after the installer. If you closed it, find Application Stack Builder in the Start menu.
  2. Pick PostgreSQL 18 on port 5432 from the list and press Next.
  3. Open Spatial Extensions and tick the PostGIS bundle for PostgreSQL 18.
  4. Press Next through the download, then run the PostGIS installer. Accept its defaults. If it offers to create a spatial database, untick that. Step 3 makes the database.

Postgres.app already includes PostGIS, so there is nothing to do here. If you used the EDB installer, follow the Windows steps.

PostGIS came with postgresql-18-postgis-3 in step 1, so there is nothing to do here.

3

Create the vicmap database and user

The client gets a database of its own, called vicmap, and a user, also called vicmap, that can reach only that database. That way the client never needs the superuser password.

  1. Open pgAdmin 4 from the Start menu. Enter the superuser password from step 1 when asked.
  2. In the tree on the left open Servers, then PostgreSQL 18, then Databases, and click postgres.
  3. Open Tools, then Query Tool.
  4. Paste the commands on the right. Run them one at a time: highlight a command, press F5, and check the Messages tab before going on to the next. The three should report CREATE ROLE, CREATE DATABASE and GRANT.

CREATE DATABASE cannot run inside a transaction blockpgAdmin shows this if you press F5 with nothing highlighted. It sends the whole script as one transaction, and PostgreSQL will not create a database inside one, so none of the commands took effect. Run them again one at a time.

  1. In Postgres.app, double-click the postgres database. A terminal opens, connected as the superuser.
  2. Paste the commands on the right and press Enter.
  1. Open a terminal and connect as the superuser with sudo -u postgres psql.
  2. Paste the commands on the right and press Enter.

About the passwordThe password vicmap is a deliberate default. Everything in this database can be downloaded again from VLRS, so it needs little protection. If your organisation has rules about passwords, or the database can be reached from the internet, choose a stronger one and use it in step 6 instead.

SQL, run as postgres 
CREATE ROLE vicmap LOGIN PASSWORD 'vicmap'
  NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION NOBYPASSRLS;

CREATE DATABASE vicmap;

GRANT CREATE ON DATABASE vicmap TO vicmap;
4

Switch on PostGIS in the vicmap database

PostGIS is installed, but each database has to switch it on for itself. This one is easy to get wrong, so check which database you are connected to.

  1. In pgAdmin, right-click Databases and choose Refresh. The new vicmap database appears.
  2. Click vicmap, then open Tools, then Query Tool. The title of the new tab should say vicmap, not postgres.
  3. Run the commands on the right. The last one should print a line starting POSTGIS="3.
  1. In the same terminal, paste the commands on the right. The first line moves you into the vicmap database.
  2. The last one should print a line starting POSTGIS="3.
  3. Type \q to leave.

Wrong database?If you run this while connected to postgres, PostGIS is switched on there instead, and the client reports that it is missing. Run it again in vicmap. It does no harm to have it in both.

SQL, run as postgres in the vicmap database 
CREATE EXTENSION postgis;
SELECT postgis_full_version();
SQL, run as postgres in the vicmap database 
\c vicmap
CREATE EXTENSION postgis;
SELECT postgis_full_version();
5

Install Python and the client

The client is a Python program. It needs Python 3.12 or later, and 3.14 is recommended.

  1. Download the Python install manager from python.org and run it.
  2. A console window then asks three questions. Answer Y to each: long path support, adding the commands directory to PATH, and installing the latest CPython. That Python includes Tk, which the client's window needs.
  3. Install Git with its defaults. It makes updating the client a one line job later.
  4. Open PowerShell from the Start menu and run the commands on the right, one line at a time.
  1. The Mac's own Python is too old. Download Python 3.14 from python.org and run the installer.
  2. Git comes with the Xcode command line tools. If git is missing the first command below offers to install them.
  3. Open Terminal and run the commands on the right, one line at a time.
  1. Check your Python with python3 -V. If it is 3.12 or later, install the extras below. If it is older, install a newer Python first.
  2. Run the commands on the right, one line at a time.

The commands download the client into a folder called VLRS in your home folder, give it a private set of Python packages, and open its window. No data is downloaded yet.

6

Register and connect the database

The window opens on Setup & QA. Work down it once. The GUI guide shows every control on this page in detail.

  1. Type your email into the registration fields and press Refresh. VLRS emails you a validation link.
  2. Open that email and click the link. Back in the window, press Refresh again. Both registration checks turn green.
  3. Fill in the database fields: Endpoint localhost, Instance vicmap, Port 5432 (or the port from step 1), Username vicmap and Password vicmap, or the password you chose in step 3.
  4. Check Bin path. It should be the folder holding pg_restore. The usual one is filled in for you: C:\Program Files\PostgreSQL\18\binfor Postgres.app change it to /Applications/Postgres.app/Contents/Versions/18/bin/usr/lib/postgresql/18/bin.
  5. Press Test database. It checks the connection, the client tools, PostGIS and the client's own tables, and creates those tables the first time. All four should turn green.

If a check stays red, the status bar at the bottom says why. The most common causes are a wrong password, a bin path pointing at an older PostgreSQL, and PostGIS switched on in the wrong database (step 4).

Prefer the command line? The same setup without the window.

Run setup twice. The first run registers your email and stops while you click the validation link. The second fetches your API key, asks for the database details and runs the same four checks. Press Enter at a question to accept the default shown in brackets. Lines in yellow are what you type.

7

Choose your layers

Nothing is switched on to start with, so nothing downloads until you choose.

  1. Open the Meta tab.
  2. Pick a schema on the left, such as vmadmin for administrative boundaries or vmadd for addresses.
  3. Tick the layers you want. All on ticks every layer in that schema. Each tick is saved straight away.
  4. Click a layer's name to see its columns and its update history.
  5. The vmhist schema holds the history archives, every past version of the VLAT and VTT layers. Leave it unticked unless you need that history.

Not sure what you need?Start small. Everything together is about 150 GB and takes hours the first time, and the vmhist history archives are most of that. A handful of schemas such as vmadmin takes minutes, and you can tick more later.

8

Run your first sync

A sync downloads every ticked layer you do not have yet, and brings the ones you have up to date.

  1. Go back to Setup & QA and press SYNC.
  2. The button reads SYNCING and a bar moves in the status bar. You can keep using the window.
  3. Progress is written to the terminal you started the client from, and to the file deltaVic.log in the VLRS folder.
  4. When it finishes, the Replication counts on Setup & QA show how many layers are active and how many are in error. Errors should be 0.

The terminal shows each layer as it is fetched. In a line such as (VLAT:-1:full)-->(656:full) the left side is what you held, where -1 means nothing yet, and the right side is the supply being loaded. A full supply is a complete copy, an inc is just the week's changes.

Do not edit the synced tablesEach update is checked against VLRS. A table that has been edited no longer matches, and that layer stops updating until it is reloaded. Copy what you want to change into a schema of your own first.

9

Look at what arrived

Each Vicmap schema is now a schema in your vicmap database, and each layer a table.

  1. Install DBeaver, a free database browser that can draw maps.
  2. Add a PostgreSQL connection: host localhost, port 5432, database vicmap, username vicmap, password vicmap.
  3. Open vicmap, then Schemas, then a schema such as vmadmin, and double-click a table.
  4. On the Data tab, click a geometry cell, then the Value panel's map view, to see the shapes on a map.

QGIS reads the same database, through Layer, Add Layer, Add PostGIS Layers, with the same connection details.

To see what you hold and when it last changed, run this in DBeaver's SQL editor:

SQL 
SELECT identity, sup, sup_ver, sup_type, status, err, edit_date
  FROM vm_meta.data
 WHERE active
 ORDER BY edit_date DESC;
10

Keep it up to date

The client only fetches changes when a sync runs, so on its own your copy stays as it was on the day of step 8. Schedule a sync every hour and it follows Vicmap within the hour. Run it at some minute past the hour rather than on it, so not everyone asks VLRS at once.

  1. Open Task Scheduler from the Start menu and choose Create Task.
  2. General: name it VLRS sync, and choose Run whether user is logged on or not.
  3. Triggers: New, Daily, starting at a time such as 00:17, with Repeat task every 1 hour for a duration of Indefinitely.
  4. Actions: New, Start a program, filled in as in the table.
  5. Settings: set If the task is already running to Do not start a new instance.
Program/scriptC:\Users\you\VLRS\.venv\Scripts\python.exe
Add argumentsdeltaVic.py sync
Start inC:\Users\you\VLRS

Start in mattersLeave it empty and the task runs somewhere else, finds no settings, and does nothing useful.

  1. Open the schedule with crontab -e.
  2. Add the line on the right, with your own minute in place of 17 and your own path in place of the home folder.
  3. Save and close. It runs at that minute every hour.

A first sync can take hours, and cron starts the next run on time regardless. flock skips a run while the last one is still going. macOS does not have it, so install it with brew install flock or leave that part out.

crontab 
17 * * * * cd $HOME/VLRS && flock -n /tmp/vlrs-sync.lock .venv/bin/python deltaVic.py sync >/dev/null 2>&1

A systemd timer runs the sync every hour, at a minute of its own choosing, and never starts a new one while the last is still going.

  1. Create the two files on the right as root, for example with sudo nano /etc/systemd/system/vlrs-sync.service. Put your own username in place of you.
  2. Switch the timer on with the first two commands below.
  3. The third shows when it runs next. The fourth shows what the last runs printed.
Terminal 
sudo systemctl daemon-reload
sudo systemctl enable --now vlrs-sync.timer
systemctl list-timers vlrs-sync.timer
journalctl -u vlrs-sync.service -e

No systemd?Use cron instead, installing it with sudo apt install cron if it is missing. Cron starts a run on time even when the last is still going, so the line puts flock in front to skip that run. Add it with crontab -e:

crontab 
17 * * * * cd $HOME/VLRS && flock -n /tmp/vlrs-sync.lock .venv/bin/python deltaVic.py sync >/dev/null 2>&1
/etc/systemd/system/vlrs-sync.service 
[Unit]
Description=VLRS sync
Wants=network-online.target
After=network-online.target postgresql.service

[Service]
Type=oneshot
User=you
WorkingDirectory=/home/you/VLRS
ExecStart=/home/you/VLRS/.venv/bin/python deltaVic.py sync
TimeoutStartSec=infinity
/etc/systemd/system/vlrs-sync.timer 
[Unit]
Description=Run the VLRS sync hourly

[Timer]
OnCalendar=hourly
RandomizedDelaySec=1h
FixedRandomDelay=true
Persistent=true

[Install]
WantedBy=timers.target

The main Vicmap updates usually land on Friday night, and an hourly sync picks up everything else as it happens. After the first download, a weekly update of everything normally takes under 10 minutes. If yours regularly takes much longer, tell the Vicmap team at vicmap.help@transport.vic.gov.au.
